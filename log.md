## 2026-08-30 — brochure-video : OOM ffmpeg sur l'EC2 dédié corrigé par ajout de swap

[2026-08-30] Après le déploiement du fix `mime_type`, l'utilisateur signale qu'une brochure reste bloquée ~10 min côté UI sans jamais aboutir. `journalctl` sur l'EC2 `moana-brochure-video` (51.45.17.78, 1.9 Go RAM, 0 swap) montre que le noyau a tué `ffmpeg` par OOM pendant l'assemblage des clips (transitions `xfade`), sans que le process ait pu écrire de statut d'erreur — d'où le blocage silencieux. Pas de changement de code, pas de resize d'instance. Résiduel non traité : un job tué par OOM/SIGKILL ne remonte toujours pas d'état d'échec exploitable côté UI (le polling tournerait à nouveau indéfiniment si l'OOM se reproduisait malgré le swap) ; si l'usage swap devient fréquent, alléger le filtergraph ffmpeg ou upgrader l'instance. Détail : `journalbug.md`.

## 2026-08-30 — yatco-global : 502 brochure BOSS résolu (config Vercel, pas de code)

[2026-08-30] Résolution de l'incident brochure YATCO Global (502 « Brochure indisponible ») documenté depuis `045ee59` et 7 tentatives de correctif de code infructueuses. Diagnostic mené avec accès réel (clé SSH récupérée d'un résidu de test, `vercel login`, creds AWS locales) : le script distant et le backend EC2 fonctionnaient déjà correctement (reproduits hors Vercel via `ssh` et `ssh2`) ; les logs runtime Vercel (`vercel logs --follow`) ont montré la vraie cause, `ssh2: All configured authentication methods failed`. Fix : ajout de ces deux variables en Production (clé `moanakyc.pem`, hôte `ubuntu@51.44.220.145`) + redéploiement, sans changement de code. Confirmé fonctionnel par l'utilisateur en prod. Documenté : `YATCO_BROCHURE_ATTEMPTS.md` (résolution en tête), `journalbug.md` (entrée mise à jour), nouveau `wiki/YATCO-Brochure-Diagnostic.md` (méthode de diagnostic pas à pas, réutilisable pour tout futur « ça marche partout sauf depuis Vercel »).

Un agent de codage autonome (Codex/GPT-5.6) sans contre-instruction système et sans sandbox traite naturellement toute demande comme une tâche à exécuter lui-même — d'où le symptôme exact rapporté.

Le fichier n'a jamais été commité entre-temps : seul le typo traînait comme diff local non validé.

**Fix appliqué :**
- `dev/software_factory/tmux_factory.sh` : configuration d'origine restaurée (`claude`/Sonnet 5, effort high, system prompt + `--allowedTools`/`--disallowedTools` réels, Bash restreint à `./run_background.sh`). Commentaire de tête corrigé (décrivait encore Codex) et note anti-régression ajoutée.

- Détail complet et résiduel non traité (les 4 Team Leads tournent encore sur le même patron non protégé `codex`/`gpt-5.6-sol`/bypass) : voir `journalbug.md`.

## 2026-08-27 — Brochure-video : interface muette sous React Strict Mode corrigée

[2026-08-27] Le clic « Générer la vidéo » pouvait lancer le POST et le worker distant sans afficher la barre de chargement, le suivi ni le résultat dans `next dev`. La cause était le cycle de développement React Strict Mode `setup → cleanup → setup` : `useBrochureVideoJob` conservait son `BrochureVideoJobController` dans un `useRef`, mais le premier cleanup appelait `dispose()` et laissait définitivement `disposed=true`. Le second setup se réabonnait au même contrôleur sans le réactiver ; les notifications React étaient alors ignorées et le traitement s'arrêtait côté client après le POST. Correction dans `lib/hooks/useBrochureVideoJob.ts` : ajout de `activate()`, réactivation à chaque setup de l'effet et refus explicite de `submit()` après un vrai démontage. Test de non-régression ajouté dans `tests/frontend/brochure-video-page.test.ts` avec la séquence Strict Mode exacte ; **11/11 tests frontend passent** et `tsc --noEmit` est propre. Les avertissements Firefox sur les polices `.woff2` préchargées étaient sans rapport avec le bug.

[2026-08-27] Un second essai du même PDF terminait sur `definitive:RuntimeError` après réutilisation des 9 clips Veo. La vidéo finale existait pourtant dans Supabase (6,49 Mo). `SupabaseStoragePublishCheckpoint.load_confirmed()` attendait un champ JSON `checksum` absent de la vraie réponse `object/info` Supabase ; il déclarait donc l'objet absent, réassemblait la vidéo et tentait une création conditionnelle sur la même clé. Le refus de doublon était ensuite réduit au seul nom `RuntimeError`. Correction dans `workers/video_assembler.py` : vérification des objets Supabase existants par téléchargement et SHA-256 de leurs octets, plus conservation du détail des exceptions dans la dead-letter. Correction préventive dans `workers/brochure_video_runner.py` : recherche de la vidéo finale vérifiée avant classification Gemini et avant Veo, afin qu'un nouvel essai du même PDF ne consomme aucun crédit.
